# Sustained improvement after acceptance

## Workflow

1. Read the poteto-mode principles and ground the actual run outcomes. Complete.
2. Preserve the frozen v2 experiment, costs, source and post-run failures. Complete.
3. Define the continuation policy and durable context checkpoint.
4. Change the shared prompt, finish gate and context management together.
5. Add regression tests for early finish, context overflow, retained artifacts and spending continuity.
6. Publish regenerated packets, verification evidence and a walkthrough. Do not rerun paid experiments as part of this prompt change.

## Definition of done

Passing acceptance or completing one/two optimizations cannot finish an agent while useful capacity remains. The prompt specifies a repeated hypothesis/change/measure/keep-or-revert loop with security and stability work. Short remaining time or inconclusive performance redirects to bounded tests. Context rollover preserves the public contract, incumbent, latest source, experiment evidence and model-authored notes without resetting the dollar or token ledger.

The control records are an improvement journal and a controller-built context checkpoint. They belong to a run, not another level. The runner remains the only authority over termination, admission and retained artifacts. Test cases and model self-assessments are evidence, not proof of security.

Throughput checkpoint: preserve the v2 evidence first; then test the stop policy and bounded context reset with a fake API before any new paid call. Native delegation remains unused because its exposed API lacks a service-tier selector. Independent review is not claimed.

Alternatives considered: prompt-only encouragement leaves the existing finish and context exit paths intact; increasing the context ceiling merely postpones exhaustion and changes reservation assumptions. Keep the existing metering bounds and replace stale conversational history with an explicit same-run checkpoint.

Encode Lessons in Structure changed two runtime boundaries: finish no longer accepts an arbitrary attempt-count milestone, and request counting triggers a durable context checkpoint before admission. Prove It Works changed validation: restart checks run real fresh sandboxes, server diagnostics survive evaluation, and a failed revalidation invalidates the original acceptance claim. The tests exercise both early final-message and finish-tool paths.

The new prompt requires security work but does not certify security. Existing conservative promotion gates remain authoritative; speculative or unmeasured security changes are archived rather than silently replacing the incumbent. Positive evidence of better performance/security under the new loop still requires a future paid experiment. The new loop has been validated with fake API responses and real sandbox fixtures, not a new live Luna run.
